Booking Availability Monitor

Licence in Dental Surgery Part 2 Exam — February 2027

A browser-only watcher for the Royal College of Surgeons of England exam booking page on Eventbrite. It checks whether a ticket can genuinely be selected and alerts you by desktop notification and Telegram the moment that changes. No backend, no database, no paid hosting.

1 How this works

Two pieces, and only one of them does the monitoring.

This page cannot monitor anything, and it cannot show you live status.

A page served from logeshsharma.github.io is a different browser origin from eventbrite.co.uk, and it has no access to Tampermonkey's storage. There is no safe, reliable way to bridge the two without a backend — so this site deliberately does not try. Every live number lives in the userscript panel on the Eventbrite page itself. Nothing on this page is a live reading.

Component A

This dashboard (GitHub Pages)

Setup instructions, the userscript installer, the Telegram walkthrough, and a working test of your browser's notification permission. A static site — that is all it can be.

Component B

The Tampermonkey userscript

3 How availability is decided

A visible button is not availability. Three independent signals are read, and a ticket must be genuinely orderable.

SignalSourceWhat it proves
salesStatus The page's own __NEXT_DATA__ payload Eventbrite's internal verdict: sold_out, on_sale, sales_ended…
offers.availability schema.org JSON-LD in the page head Independent corroboration: SoldOut vs InStock
Sold-out marker conversion-bar-sold-out-signal in the DOM Vetoes an “available” reading if it is still present
has_available_tickets
maximum_quantity_per_order		 Eventbrite checkout widget inventory The decisive test — whether a quantity can actually be selected

The rules that prevent false alarms

  • Available requires the inventory to report available tickets and at least one ticket row whose per-order maximum is above zero.
  • A ticket row that renders but caps quantity at 0 is not availability — that is exactly the “button exists, booking doesn't” trap.
  • Sold out with an open waitlist is still sold out. Joining a waitlist is not booking.
  • If two signals disagree about whether you can book, the result is Unknown — never “available”.
  • If Eventbrite serves a bot check, a queue page, or anything unparseable, the result is Unknown.

The states you will see

Available Possibly available (unconfirmed) Sold out Not yet on sale Sales ended Unknown

Possibly available means the listing suggested an opening but the inventory check could not confirm it. It still alerts you — for a £1,793 exam seat a clearly-labelled maybe beats a missed opening — but it is explicitly not a confirmed result.

4 Install the monitor

Two minutes, desktop Chrome, Edge, Firefox or Safari.

  1. Install the Tampermonkey extension — Chrome / Edge, Firefox, or Safari.
  2. Click Install the userscript below. Tampermonkey opens its install screen — review the permissions and confirm.
  3. Open the Eventbrite booking page. A Booking Monitor panel appears in the bottom-right corner.
  4. Set your interval (30 minutes by default), optionally add your Telegram details, and press Save settings.
  5. Press Start. Allow notifications when the browser asks. Leave the tab open.

The tab has to stay open. This is a browser script, so it only runs while the browser is running and the machine is awake. Close the tab, quit the browser, or let the laptop sleep and checking stops until you come back.

Telegram alerts

Never type your bot token into this page. It is a public website. There is deliberately no token field here. Your credentials belong only in the userscript panel on the Eventbrite page, where Tampermonkey keeps them on your own computer.

  1. In Telegram, message @BotFather and send /newbot. Follow the prompts; it replies with a bot token like 123456789:AAE….
  2. Open a chat with your new bot and send it any message — a bot cannot message you first.
  3. Get your chat ID by opening this URL in a browser tab, with your real token substituted in: 
    https://api.telegram.org/bot<YOUR_TOKEN>/getUpdates
    Find "chat":{"id":123456789} in the response. That number is your chat ID.
  4. Paste both values into the userscript panel on the Eventbrite page, press Save settings, then press Test Telegram.

Keeping the token safe

  • It is stored in Tampermonkey's local storage on this computer only — never committed to this repository, never sent anywhere except api.telegram.org.
  • Anyone with access to your browser profile can read it. Treat it like a password.
  • If it leaks, send /revoke to BotFather and issue a new one.
  • A bot token lets someone post as your bot. It does not give access to your Telegram account.

6 What it will and will not do

The honest limits, so a missed alert is never a surprise.

It does

  • Check on your interval, 30 minutes by default
  • Survive page refreshes and browser restarts
  • Catch up straight away after sleep or throttling
  • Alert once per genuine transition into availability
  • Verify real ticket inventory, not button presence
  • Warn you in the panel if checking has stalled
  • Keep one check in flight at a time, across tabs
  • Report Unknown rather than guess

It does not

  • Buy tickets or fill in any booking form
  • Touch CAPTCHA, logins, or the Eventbrite queue
  • Run with the browser closed or the machine asleep
  • Promise checks land at exactly 30-minute marks
  • Show live status on this GitHub Pages site
  • Send your credentials anywhere but Telegram

On timing

Browsers throttle timers in background tabs and freeze them when a machine sleeps, so a check scheduled for 30 minutes away can land late. The script stores a deadline rather than trusting a timer, and checks whether it is overdue every 15 seconds and whenever the tab regains focus — so it catches up quickly. It cannot run while the browser is closed, and it does not pretend otherwise. The panel shows a stall warning when a check is badly overdue.
